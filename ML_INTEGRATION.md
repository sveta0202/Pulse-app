# Подключение ML-модели к сайту PULSE

## Что требуется от разработчика

Нужно заменить **только** заглушку `model_adapter.py` на реальный инференс. На сайте НЕ нужно добавлять кнопки выбора модели или поля настройки ML.

Контракт:

```text
Пользователь                     Python-сервер                       Браузер
  EMG (.npy/.csv)     ->  POST /api/predict        ->    CSV angle_00 … angle_19
                            запуск ML-инференса             проверка CSV
                                                             3D-кисть + экспорт CSV/PNG
```

## 1. Формат входных данных

- Формат: `.npy` с массивом `float32` или `float64` размерности `(T,6)`, либо CSV с шестью числовыми каналами на строку.
- Частота набора AIRI: **500 Гц**.
- Для `npy` поддерживаются little-endian `float32`/`float64`, C-order.
- Нельзя допускать `NaN`, `Infinity`, неверное количество каналов.
- Сайт отправляет **исходный файл**, а не отрендеренный график или предварительно нормализованный массив. Вся обработка и нормализация модели должны быть на сервере.

HTTP-запрос:

```http
POST /api/predict HTTP/1.1
Content-Type: application/octet-stream
X-Filename: rec_001.npy

<сырые байты файла>
```

Ответ (успех): `200 OK`, `Content-Type: text/csv; charset=utf-8`, тело — непосредственно CSV. Не JSON, не адрес файла, не base64.

Если модель отсутствует, сервер возвращает `501`. При ошибочных входных данных — `422`. При ошибке инференса — `500`. Фронтенд показывает ошибку и не создаёт фиктивные результаты.

## 2. Формат выходного CSV

Минимально **обязательные** поля в строке заголовка:

```text
angle_00,angle_01,angle_02,angle_03,angle_04,angle_05,angle_06,angle_07,angle_08,angle_09,angle_10,angle_11,angle_12,angle_13,angle_14,angle_15,angle_16,angle_17,angle_18,angle_19
```

Каждая строка: 20 конечных чисел в **радианах**. Имена и порядок колонок строго определены, но дополнительные служебные столбцы допустимы, например `row_id`, `recording_id`, `sample_index`. Если `recording_id` указан, CSV может содержать несколько записей; версия интерфейса показывает первую запись. Для текущего сценария рекомендуется возвращать **одну запись** на загруженный файл.

**Для официального конкурса** нужен формат 23 столбца:

```text
row_id,recording_id,sample_index,angle_00,...,angle_19
```

Идентификаторы и набор строк нужно брать из официального `sample_submission.csv` **текущего этапа**. Их нельзя придумывать из номера строки или файла. Если официальный шаблон недоступен, формируйте визуализационный CSV (20 углов); такой файл нельзя автоматически считать готовой конкурсной отправкой. В AIRI первые 1000 временных отсчётов тестовой записи — контекст, для метрики нужны значения с `sample_index >= 1000`. Подаваемый в модель сигнал при этом содержит начало записи.

## 3. Соответствие углов суставам

| Индексы | Палец | Углы (в порядке полей) |
|---|---|---|
| `angle_00`–`angle_03` | Указательный | MCP θ, MCP φ, PIP, DIP |
| `angle_04`–`angle_07` | Средний | MCP θ, MCP φ, PIP, DIP |
| `angle_08`–`angle_11` | Мизинец | MCP θ, MCP φ, PIP, DIP |
| `angle_12`–`angle_15` | Безымянный | MCP θ, MCP φ, PIP, DIP |
| `angle_16`–`angle_19` | Большой | MCP θ, MCP φ, PIP, DIP |

Мизинец идёт **перед** безымянным. Этот порядок взят из `angle_info.json` датасета AIRI.

Важно: **нельзя** при движении указательного пальца принудительно обнулять все другие. Прогноз каждого отсчёта содержит положение **всех пяти пальцев одновременно**. Кинематика применяется к единой строке из 20 значений, а сгибания MCP/PIP/DIP накопительно поворачивают фаланги.

## 5. Интеграционная проверка

1. `python server.py` из каталога сайта.
2. Проверка API до подключения: ожидается `HTTP 501` и **отсутствие** CSV.
3. После подключения загрузить известную реальную ЭМГ `(T,6)` и проверить размеры предсказания `(T,20)`.
4. Проверить, что `angle_08`–`angle_11` двигают **мизинец**, а `angle_12`–`angle_15` — **безымянный**.
5. Открыть сайт, загрузить только входную ЭМГ, нажать «Обработать».
6. Проверить скачивание CSV и PNG, сопоставить значения углов на экране с CSV.
7. Проверить отсутствие `NaN/Inf`, сохранение `recording_id`/`sample_index` и формат конкурса при отдельном submit-пайплайне.

## 6. Примечания по развёртыванию

- Публикуйте сервер по HTTPS и ограничивайте размер входных файлов; для локального прототипа ограничение — 100 МБ.
- Если сервер работает отдельно от сайта (другой домен), настройте обратный прокси для `/api/predict`, либо CORS на сервере. В текущем варианте фронтенд использует относительный адрес `/api/predict` и **не требует** у пользователя указывать адрес модели.
- Для больших `(T,20)` CSV нужна потоковая выдача или ограничение размера: текущая реализация загружает весь CSV в память браузера.
- По умолчанию интерфейс визуализирует только **первую запись** ответа, а CSV сохраняет целиком.
- Кинематика предназначена для демонстрации относительных движений, но не для точного биомеханического восстановления кисти из 20 углов без отдельной калибровки костных размеров, ориентаций MCP и суставных осей.
